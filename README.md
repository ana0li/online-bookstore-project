### Проект: Веб-версия книжного магазина (Кейс-задача №4)

Разработано в рамках производственной практики студентки Университета «Синергия».

#### ➔ Реализованный функционал:
* Интерфейс пользователя: Просмотр каталога любимых книг, фильтрация и многофакторная сортировка (по категориям, авторам и году написания).
* Система аренды: Функция покупки книги или оформления аренды на фиксированные сроки (2 недели / 1 месяц / 3 месяца).
* Панель администратора (Admin Dashboard): Полноценный интерфейс для управления списком книг, изменения цен, отслеживания статусов доступности.
* Автоматизация: Логика для автоматического напоминания пользователям об окончании срока аренды книги.

---

#### ➔ Подробный анализ выполненной задачи (7 ключевых пунктов)
1. Проектирование базы данных: Реализована реляционная структура данных с чётким разделением сущностей (Книги, Авторы, Жанры, Статусы экземпляров).
2. Разграничение прав (RBAC): Настроена ролевая модель доступа. Обычные пользователи имеют права только на просмотр и заказ, администраторы — на полное редактирование (CRUD).
3. Многофакторная фильтрация: Поиск по каталогу оптимизирован с помощью SQL-фильтров, что позволяет мгновенно сортировать книги по году, жанру и автору.
4. Управление бизнес-логикой: Внедрена система учета экземпляров. Книга автоматически меняет статус на "В аренде" или "Доступна", исключая двойные заказы.
5. Временные интервалы (Логика дат): Реализован расчет сроков возврата на базе периодов в 14, 30 и 90 дней с привязкой к часовому поясу сервера.
6. Автоматизация уведомлений: Архитектура проекта предусматривает фоновые задачи для проверки истекающих сроков аренды и отправки email-напоминаний.
7. Эргономика интерфейса (UX): Административная панель кастомизирована для удобного массового изменения цен и ручной смены статусов книг.

---

#### ➔ Рекомендации по устранению выявленных ошибок
* Проблема с временными зонами: Использовать встроенные модули работы со временем (`django.utils.timezone`) для избежания сдвигов при расчете даты возврата.
* Дублирование авторов при заполнении: Вынести сущности "Автор" и "Категория" в отдельные связанные таблицы (Foreign Key) для сохранения целостности БД.
* Уязвимость панели администратора: Изменить стандартный URL-адрес админки /admin/ на скрытый уникальный путь для защиты от подбора паролей.
* Избыточная нагрузка на БД: Добавить индексацию для полей «Год написания» и «Автор», чтобы ускорить поиск при масштабировании магазина.
